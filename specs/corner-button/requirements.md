# 角落按钮：需求

在「在浏览器打开仓库」插件上做增量：**在对话界面右下角放一个常驻按钮，点一次就在默认浏览器打开当前仓库**。命令 `/gitweb` 保留。

## 目标

- 对话界面右下角常驻一个小按钮，点一次就用默认浏览器打开当前仓库。
- 只在**对话界面**里出现：切到设置页、定时任务页、插件页必须收起，回到对话界面再出现。
- 只在**能打开**时出现：当前项目根有 origin，且 origin 能规范成 http(s)。没有工作目录、没有 origin、origin 不能变成网页，或探测失败，都不画按钮。
- 按钮画出来之前先探测一次；探测不打开浏览器、也不弹提示。

## 验收

- 显示条件一（页面）：宿主渲染出输入框（`.composer-shell`）且该输入框确实露在屏幕上（左半中点命中测试通过）才画；没有输入框、输入框没尺寸、被整页界面盖住、或停在设置页（`.app-shell.settings-mode`）都不画，已经画出来的立刻收掉。
- 显示条件二（可打开）：探测派发一次 `plugin.call`，`method` 为 `hasGitRemote`；只有返回 `hasRemote: true` 才画，`false` 或宿主拒绝都不画。这一次探测不拉起浏览器、不弹提示。
- 探测按**工作目录缓存**：目录没变就直接用上一次的结论，避免每次 DOM 变动都拉起 `/usr/bin/git`；目录变了或缓存为空才真跑一次。
- 点击时**重新读一次** origin（不读缓存），保证用户改了 origin 立刻生效。
- 按钮没显示期间最多每 1.5 秒重新问一次；切到有 origin 的项目（工作目录变了）时按钮能自己回来。
- 点击打不开时：先把原因留在按钮的悬停提示上（`失败` 态），约 2.8 秒后再把按钮收掉。
- 插件不注册任何插槽，也不依赖 react；加载时先清掉上一次残留的层（`.pogw-corner`），避免旧层一直挂在窗口上。
- 同一界面上只画一颗按钮，反复探测也不会叠层。
- 角落按钮的文案 en / zh-CN 两份，界面上不留写死的可见文案。

## 右下角按钮带（跨插件约定）

宿主没有「角落」槽位，每个插件都自己往右下角画，位置只能插件之间自己协商。约定：

- 凡是在窗口右下角画常驻按钮的插件，都给按钮加属性 `data-pi-corner-button`（空值），加入同一条按钮带。
- 同一窗口里所有带这个属性的按钮按 **DOM 顺序** 从下往上排：文档里靠前的贴右下角。
- 第 i 颗按钮向上让位 `Σ(下面每颗按钮的高度) + 8px × i`，用 `transform: translateY(-Npx)`，只改绘制不改布局。
- 高度取 `getBoundingClientRect().height`；隐藏（高度为 0）的按钮跳过、不占位。
- 每颗按钮只写自己的内联样式，不碰别家的元素；值没变就不写，免得自己触发自己的 `MutationObserver`。
- 显示按钮时、以及每次 DOM 变动时各重排一次，别的插件出现或消失都能跟上。
- 想移动位置（例如改到左下角）时整条带一起改，不要只改自己那颗。

## 约束

- 渲染器只用一个动作 `plugin.call`；方法名必须列在 `manifest.rendererCallMethods`（`hasGitRemote` / `openGitWeb`）。
- 渲染器模块必须是无构建 ES 模块，不能用 JSX、不能依赖 npm 包；这一版连 react 都不用。
- 自绘层的盒子必须 `pointer-events: none`，只有按钮 `auto`：否则命中测试会打到插件自己那颗按钮上（`elementFromPoint` 会跳过 `pointer-events: none` 的元素）。
- 目录来源只有 `pi.workspace.get()` 的项目根，不做任何路径推断。

## 不做

- 不用 `composerControl` 插槽判断页面：设置页下对话框仍挂着（只是被盖住），插槽的卸载回调根本不触发。
- 不用独立浮窗 `ui.panel` + `ui.shape: "widget"`：宿主不给窗口坐标，位置不可控，只能落在屏幕正中。
- 不猜临时会话的目录，也不给临时会话任何替代入口。
- 不为「切会话」订阅任何事件：宿主没给这类通知，改用「进出对话界面时探测 + 点击时发现」两条兜住。
- 不引入依赖、不加构建步骤、不新增 `shell.openExternal` / `notify` 之外的权限。
- 不指望宿主替插件排位置：0.16.1 的 `rendererSlots` 里没有角落槽位，宿主 CSS 里那个 `.p-overlay__corner` 也没人用。要根治得让宿主提供 corner 槽位（还没提需求，见 dev-cycle 的下一步），在那之前用上面那条约定。
